# ED-M09 - Input Authoring

Status: `planned; IQ-1 decided; design awaiting owner review (M09.1)`

| Users create and edit input actions and mapping contexts in the editor, bind keys and mouse input by pressing them, configure triggers, rename with retargeting, save, cook and use them in Play (REQ-045). | M09.1 owner review of the [input authoring LLD](../lld/input-authoring.md) and the [findings](#findings-from-the-analysis), then M09.2–M09.10. | None yet; the LLD's [gates](../lld/input-authoring.md#14-validation-gates) define it. |

The [input authoring LLD](../lld/input-authoring.md) owns the workflow,
format, editors, commands, diagnostics, gates and open questions. This plan
owns order, dependencies and acceptance.

## Starting point

- The engine imports, cooks and runs input actions and mapping contexts; its
  formats are the authoring format.
- ED-M08.10o cooks hand-written input files under authoring mounts and lists
  their assets in pickers; ED-M08.10p–q add script parameters and the scene's
  Play section that reference them
  ([script authoring](../lld/script-authoring.md)).

## Findings from the analysis

Bugs, redundancies and inconsistencies found while reading the engine's input
code, its design documents and the editor designs. Every engine item below is
fixed in M09.2, before any input UI slice starts: the editor exposes engine
behavior, so it must not be built on behavior that is wrong or about to
change. Features the engine lacks are listed separately as
[engine gaps](../lld/input-authoring.md#151-engine-gaps).
