# ED-M09 - Input Authoring

Status: `planned; IQ-1 decided; design awaiting owner review (M09.1)`

| Outcome                                                                                                                                                                                                     | Remaining                                                                                                                                      | Evidence                                                                              |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Users create and edit input actions and mapping contexts in the editor, bind keys and mouse input by pressing them, configure triggers, rename with retargeting, save, cook and use them in Play (REQ-045). | M09.1 owner review of the [input authoring LLD](../lld/input-authoring.md) and the [findings](#findings-from-the-analysis), then M09.2–M09.10. | None yet; the LLD's [gates](../lld/input-authoring.md#14-validation-gates) define it. |

The [input authoring LLD](../lld/input-authoring.md) owns the workflow,
format, editors, commands, diagnostics, gates and open questions. This plan
owns order, dependencies and acceptance.

## Starting point

- The engine imports, cooks and runs input actions and mapping contexts; its
  formats are the authoring format.
- ED-M08.10o cooks hand-written input files under authoring mounts and lists
  their assets in pickers; ED-M08.10p–q add script parameters and the scene's
  Play section that reference them
  ([script authoring](../lld/script-authoring.md)).

## Findings from the analysis

Defects and inconsistencies found while reading the engine's input code and
the editor designs. Each has a fix, a pass/fail check and an owning slice;
the owner may decline an engine fix at M09.1, in which case the editor
handling in the last column is what ships. Features the engine lacks are
listed separately as [engine gaps](../lld/input-authoring.md#151-engine-gaps).

| IF-1 | 1        | **Scale and bias are cooked but never applied.** The cooker writes `InputActionMappingRecord::scale`/`bias`; `HydrateInputContext` builds `InputActionMapping(action, slot)` without them and `InputActionMapping` has no such fields ([hydration](../../../projects/Oxygen.Engine/src/Oxygen/Content/Internal/InputContextHydration.cpp), [mapping](../../../projects/Oxygen.Engine/src/Oxygen/Input/InputActionMapping.h)). Pass: W with scale (0, 1) and S with scale (0, −1) on one Axis 2D action give (0, 1) and (0, −1); Mouse X with scale 0.5 halves the delta. | M09.2 | Fields hidden; hand-written values kept; `OXE.INPUT.SCALE_BIAS_IGNORED` (info).      |

| IF-3 | 3        | **A mapping without triggers never fires.** `triggers` is optional with default `[]`; `InputActionMapping` returns early when it has no triggers.                                                                                                                                                                                                                                                                                                                                                  | A mapping written as just action and slot cooks and does nothing.                                                                                            | Owner choice: schema requires at least one trigger (or `trigger`), or the runtime treats an empty list as one implicit Down. | IF-4 | 4        | **`action_chain` without `chord_action` is accepted and then dropped.** The schema requires `chord_action` only for `chord`; hydration logs `input.context.hydration_failed` and skips the trigger.                                                                                                                                                                                                                                                                                                | The mapping cooks, then runs without that trigger, so it fires when it should be gated.                                                                      | Schema requires `chord_action` for `action_chain`. Pass: schema tests reject `/`, `.`, `..` and `:`.                                                                                                                                 | M09.2 | `OXE.INPUT.NAME_INVALID` for new names; warning for hand-written ones.               |
| IF-7 | 7        | **Same-named assets from different files silently overwrite each other.** Keys derive from names; `AssetEmitter::Emit` rewrites a descriptor whose key already exists. The cooker checks only an action's value type against mounted actions, and contexts not at all across files. The engine design says it "validates consistency and skips re-emission"; it does not.                                                                                                                          | Two contexts named `Gameplay`, or one action declared with different `consumes_input`, give whichever cooked last.                                           | Cooker error when the root already holds the key from another source with different content. | IF-8 | 8        | **Unknown slots: warning at cook, dropped at run.** The cooker reports `input.context.slot_unknown` as a warning and keeps the name; hydration logs an error and drops the mapping.                                                                                                                                                                                                                                                                                                                | A typo in a slot cooks successfully and the binding is missing at run time.                                                                                  | Cooker reports an unknown slot as an error. Pass: cooker test fails the job.                                                                                                                                                    | M09.2 | `OXE.INPUT.SLOT_UNKNOWN` blocks cook; the key selector cannot produce one.           |
