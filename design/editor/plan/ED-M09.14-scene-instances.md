# ED-M09.14 - Scene Instances And The Model Editor

Status: `in_progress`

Last Updated: 2026-10-25

**Summary:** the implementation plan of
[ED-M09](ED-M09-v01-gaps-and-blocking-issues.md) item 14, #77 slice 77.8:
instancing imported models and authored scenes in scenes, with nesting, the
Model Editor, and the model import those need. The design is complete in the
documents of [section 3](#3-required-llds); this plan orders the work into
slices, the engine's first, and says which document each slice implements.

## 1. Purpose

A scene can place an imported model (`Car.glb`) or an authored scene
(`Watchtower.oscene`) as an instance: the instanced nodes appear under one
instance root, stay linked to their source, follow it on reimport and take the
scene's changes; the Model Editor shows what an import gave and tunes it.
Item 14 is too large for one ledger row: the change set spans the cooked
format, the importer, the runtime, Interop, every scene view, the cook and two
new editor modules. This plan is where its slices are tracked.

## 4. Scope

Everything specified by NGN1 to NGN14, ED1 to ED12, M-NGN1 to M-NGN10 and
M-ED1 to M-ED9, with the format release and recook of scene instances section
7.15.

## 5. Non-Scope

- Merging the ImportTool's and the editor's publication systems (scene
  instances 7.14: they share the record and the import job, not publication).
- Skins, animations and morph targets: the import reports them as dropped.
- Lightmap UVs, collision generation and mesh combining (model editor 5.3).

## 6. Implementation Sequence

The engine slices come first. A slice that changes a contract the editor
consumes (the schema, the descriptor, the import job) carries the editor's
minimal consumer change in the same commit, so every commit builds and passes;
the editor's features come after every engine slice. Slices are commits on the
way to one release (scene instances 7.15): none is released alone, and the
owner recooks once, at E2.

## 8. Dependency And Execution Risks

- **E2 is the one recook.** Every other format change must land in it; a slice
  that finds it needs another format change goes back into E2 before E2 is
  committed, never after.
- **Third-party decoders (E9, E10).** meshoptimizer, Draco, libwebp and the
  Basis Universal transcoder come through Conan; the engine build rules
  (`projects/Oxygen.Engine/AGENTS.md`) apply, and a missing package is resolved
  before the slice starts.
- **Hand migrations.** E2 (recook), E6 (records) and D1 (scene files) change
  files the product will no longer read in their old form. Each migration
  keeps every source identity and node ID; the product carries no migration
  code (scene instances 7.15).
- **The editor rebuilds against each SDK change.** It refuses to cook when its
  schema copies differ from the installed ones, so E1, E2, E6 and E7 include
  the editor's schema copies.

## 9. Validation Gates

- Each slice: the _Done when_ of every capability it implements (scene
  instances sections 7 and 8, model editor section 8), with ED-M09's done gate
  (section 6) and test rules (section 4.5).
- Engine slices: explicit test executables with `--gtest_filter`; the
  generator's unit tests and its committed-output check; the Inspector's report
  schema.
- Interop and editor slices: native Interop tests and filtered runs of the
  touched projects; UI lanes go to the owner.
- After E2: the recook of scene instances 7.15 leaves no product at scene
  format 15, and a second cook does nothing.
- Item done: scene instances G1 to G10, scene composition SG-1 to SG-8 and
  model editor MG1 to MG10 pass.
